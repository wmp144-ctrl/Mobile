# سامانه مدیریت تعمیرگاه تخصصی موبایل و تجهیزات الکترونیکی

نرم‌افزار مدیریت تعمیرگاه، چندکاربره و کاملاً آفلاین برای شبکه داخلی (LAN).
مرحله ۱ (زیرساخت، معماری و سیستم امنیتی)، مرحله ۲ (مدیریت تجهیزات، پذیرش و پرونده دیجیتال
دستگاه)، مرحله ۳ (مدیریت فایل‌ها و محل نگهداری اطلاعات) و مرحله ۴ (داشبورد مدیریتی و
گزارش‌گیری تحلیلی) پیاده‌سازی و آزمایش شده‌اند.

## فناوری‌ها

| بخش | فناوری |
| --- | --- |
| رابط کاربری | React ۱۹ + TypeScript + Vite + Tailwind CSS ۴ (فارسی، RTL، تقویم هجری شمسی) |
| سرور | Node.js ۲۲+ و NestJS ۱۱ (REST API) |
| پایگاه داده | PostgreSQL ۱۸ (مهاجرت‌های افزایشی SQL) |
| احراز هویت | JWT کوتاه‌عمر + نشست چرخشی با کوکی HttpOnly |
| قفل خودکار | تشخیص بی‌کاری در کلاینت + بازکردن با رمز از طریق سرور |
| نمودارها | Apache ECharts ۶ — دونات، میله‌ای، میله‌ای افقی/انباشته، خطی، ناحیه‌ای و ترکیبی |

مستندات: [معماری](docs/ARCHITECTURE.md) — [پایگاه داده](docs/DATABASE.md) — [استقرار](docs/DEPLOYMENT.md) — [گزارش مرحله ۱](docs/PHASE-1-REPORT.md) — [گزارش مرحله ۲](docs/PHASE-2-REPORT.md) — [گزارش مرحله ۳](docs/PHASE-3-REPORT.md) — [گزارش مرحله ۴](docs/PHASE-4-REPORT.md)

## اجرای سریع (توسعه)

پیش‌نیاز: Node.js ۲۲ یا جدیدتر و یک پایگاه داده PostgreSQL.

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) تنظیمات سرور را بسازید و مقادیر DATABASE_URL و JWT_SECRET را ویرایش کنید
cp server/.env.example server/.env

# ۳) پایگاه داده را بالا بیاورید (یکی از دو روش)
npm run db:up            # با Docker
# یا: node scripts/dev-db.mjs   # PostgreSQL محلی برای توسعه، بدون نیاز به Docker

# ۴) ساخت رابط کاربری و اجرای سرور روی پورت ۳۰۰۰
npm run build
npm start
```

سپس در مرورگر `http://localhost:3000` را باز کنید. در اولین اجرا، صفحه «راه‌اندازی اولیه»
نمایش داده می‌شود و شما نام کارگاه، نام مدیر و رمز عبور مدیر کل را تعیین می‌کنید.

### اجرای حالت توسعه (Hot Reload)

```bash
node scripts/dev-db.mjs          # ترمینال ۱ — پایگاه داده توسعه (پورت ۵۵۹۷)
# در server/.env این دو مقدار را تنظیم کنید:
#   PORT=3001
#   DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5597/repair_workshop
npm run dev:server               # ترمینال ۲ — API روی پورت ۳۰۰۱
npm run dev:client               # ترمینال ۳ — رابط کاربری روی پورت ۳۰۰۰
```

کلاینت توسعه درخواست‌های `/api` را به سرور پروکسی می‌کند؛ بنابراین کوکی و مبدأ یکسان است.

## آزمون‌ها

```bash
npm run typecheck                # بررسی نوع‌ها در سرور و کلاینت
npm run test:server              # ۷۸ تست یکپارچگی با PostgreSQL واقعی
npm run test:client              # ۲۰ تست واحد و DOM
node scripts/smoke-test.mjs      # ۴۴ بررسی HTTP روی سرور در حال اجرا (SMOKE_BASE)
```

> تست‌های سرور یک PostgreSQL موقت را روی پورت ۵۵۹۸ اجرا می‌کنند و به پایگاه داده بیرونی نیاز ندارند.
> `pg_dump` در محیط آزمایش با یک ابزار کنترل‌شده شبیه‌سازی می‌شود؛ روی سرور واقعی باید نصب باشد.

## امکانات مرحله ۲

- صفحه تجهیزات با جست‌وجو، فیلتر، مرتب‌سازی، صفحه‌بندی، انتخاب ستون، چاپ و خروجی اکسل.
- فرم پذیرش کامل با کد پذیرش خودکار و یکتا، فیلدهای قابل مدیریت و رمز دستگاه رمزنگاری‌شده.
- ۱۲ وضعیت تعمیر با تاریخچه کامل (کاربر، زمان، یادداشت) و کنترل تداخل ویرایش.
- ثبت چند اقدام برای هر دستگاه (بکاپ، ریکاوری، تعمیر، تعویض قطعه و …) با حجم داده، مسیر و نتیجه.
- پرونده دیجیتال تب‌بندی‌شده: مشخصات، آورنده و مالک، وضعیت، تاریخچه، اقدامات، فایل‌ها، تصاویر و یادداشت.
- مدیریت مشتریان مستقل از تجهیزات و هشدار شناسه تکراری (IMEI/سریال) با نمایش سوابق قبلی.

## امکانات مرحله ۳

- ساخت خودکار پوشه دستگاه هنگام پذیرش با ساختار `سال شمسی/کد پذیرش/Original/Backup/...`.
- انتخاب محل اصلی ذخیره‌سازی از تنظیمات یا صفحه فایل و بکاپ.
- چند محل ذخیره‌سازی روی دیسک سرور، هارد شبکه (NAS) یا حافظه خارجی با مسیر سرور و کلاینتی.
- نمایش ظرفیت، فضای آزاد، درصد مصرف، آخرین دسترسی موفق و هشدار قطع بودن حافظه.
- ثبت چند مسیر فایل برای هر دستگاه با دسته، حجم، وضعیت بکاپ، مسیر جایگزین و یادداشت.
- جست‌وجوی فایل‌ها با کد پذیرش، IMEI، سریال، مالک یا مسیر و فیلتر وضعیت بکاپ/دسترسی.
- بازکردن پوشه از مرورگر با برنامه کمکی ویندوز و بلیت یک‌بارمصرف (`tools/storage-helper`).
- کنترل دسترسی `files.view` / `files.manage` و ثبت تغییر مسیرها در تاریخچه.

## امکانات مرحله ۴

- داشبورد مدیریتی با ۸ کارت آماری زنده از پایگاه داده: کل تجهیزات، دریافتی امروز، در حال انجام،
  انجام‌شده، ناموفق، آماده تحویل، تحویل‌داده‌شده و تعداد مشتریان.
- شش نمودار ECharts: توزیع نوع تجهیز، سازندگان، روند ماهانه پذیرش/تحویل، مقایسه سالانه شمسی،
  نوع شغل آورنده و وضعیت دستگاه‌ها.
- فیلترهای ترکیبی: بازه تاریخ، سال و ماه شمسی، نوع تجهیز، سازنده، مدل، شغل، تکنسین، وضعیت و
  نوع عملیات؛ همه کارت‌ها و نمودارها یک‌جا از API به‌روزرسانی می‌شوند.
- گزارش‌گیری پیشرفته: انتخاب چند نمودار و ترتیب آن‌ها، تعیین شاخص و فیلد گروه‌بندی، انتخاب
  ستون‌های جدول، هفت نوع نمودار، ذخیره/ویرایش/اجرای مجدد قالب گزارش با کنترل نسخه.
- خروجی PDF چندصفحه‌ای با لوگوی کارگاه (قابل تنظیم در تنظیمات)، عنوان، بازه و فیلترها، تاریخ شمسی
  و تصویر نمودارها؛ خروجی PNG هر نمودار؛ خروجی Excel و CSV سمت سرور؛ چاپ مستقیم گزارش.
- محاسبه تمام آمار در سرور و گروه‌بندی ماهانه/سالانه با توابع تقویم شمسی PostgreSQL؛ کنترل دسترسی
  با مجوزهای `reports.view` و `reports.manage`.

## ساختار پروژه

```
server/   سرویس مرکزی: API، احراز هویت، مجوزها، تاریخچه، پشتیبان‌گیری و مهاجرت‌های SQL
client/   رابط کاربری فارسی و راست‌چین
docs/     مستندات معماری، پایگاه داده، استقرار و گزارش مراحل
scripts/  ابزارهای توسعه و آزمون دود
tools/storage-helper/  برنامه کمکی ویندوز برای بازکردن پوشه‌های شبکه
```

## نکات امنیتی

- رمزها با bcrypt (هزینه ۱۲) ذخیره می‌شوند و هرگز بازگردانده نمی‌شوند.
- نشست‌ها با توکن تازه‌سازی چرخشی و کوکی `HttpOnly`/`SameSite=Strict` محافظت می‌شوند.
- تمام عملیات با بررسی مجوز نقش در سرور انجام می‌شود؛ پنهان‌کردن منو در کلاینت فقط برای تجربه کاربری است.
- هر ورود، تغییر کاربر، تغییر تنظیمات و پشتیبان‌گیری در تاریخچه ثبت می‌شود.
- پیش از بهره‌برداری، `JWT_SECRET` و رمز پایگاه داده را در `server/.env` تغییر دهید و فایل را از دسترس عمومی خارج نگه دارید.
- پوشه بکاپ مشتریان (`STORAGE_ROOT`) را از دسترس عمومی خارج و فقط برای سرویس سرور و کاربران مجاز شبکه قابل دسترس کنید.
