# راهنمای پشتیبان‌گیری و بازیابی

این سند روند ساخت، نگهداری و بازیابی نسخه‌های پشتیبان را برای مدیر سامانه و مدیر سرور توضیح می‌دهد.

## ۱. نسخه پشتیبان شامل چه چیزی است؟

هر نسخه یک **پوشه مستقل** با نام `backup-YYYYMMDD-HHMMSS` است:

| فایل | محتوا | رمزنگاری‌شده |
| --- | --- | --- |
| `manifest.json` | نسخه قالب، زمان ساخت، فهرست فایل‌ها، اندازه، SHA-256، IV و Tag | خیر (بدون داده حساس) |
| `database.dump` | خروجی `pg_dump --format=custom --no-owner` | با پسوند `.enc` در صورت فعال بودن رمزنگاری |
| `settings.json` | `app_settings`، `field_definitions` و `option_lists` | با پسوند `.enc` |
| `uploads/` | تصاویر و پیوست‌های دستگاه‌های ذخیره‌شده روی سرور (اختیاری) | هر فایل با `.enc` |

فایل‌های پوشه `STORAGE_ROOT` (پوشه‌های Original/Backup دستگاه‌ها روی هارد یا NAS) به‌دلیل حجم زیاد
داخل بسته قرار نمی‌گیرند و باید جداگانه با ابزار فایل (Robocopy یا پشتیبان‌گیری NAS) کپی شوند.

## ۲. پیش‌نیازهای سرور

```ini
# server/.env
BACKUP_DIR=D:\Backups\RepairWorkshop
PG_DUMP_PATH=C:\Program Files\PostgreSQL\18\bin\pg_dump.exe
PG_RESTORE_PATH=C:\Program Files\PostgreSQL\18\bin\pg_restore.exe
BACKUP_CRON_ENABLED=true

# عبارت عبور رمزنگاری؛ حداقل ۱۶ نویسه و در جای امن نگهداری شود.
# اگر خالی باشد، دکمه رمزنگاری در تنظیمات هشدار می‌دهد و پشتیبان رمزنگاری‌شده ساخته نمی‌شود.
BACKUP_PASSPHRASE=یک-عبارت-عبور-طولانی-و-یکتا
```

* پوشه `BACKUP_DIR` باید فقط برای کاربر سرویس و مدیر سرور قابل دسترسی باشد.
* برای حافظه خارجی یا هارد شبکه، مسیر را در «تنظیمات ← برنامه پشتیبان‌گیری ← محل نگهداری» وارد کنید
  (مثلاً `E:\RepairBackups` یا `\\NAS\Backups\Repair`). مسیر باید از دید سرویس ویندوز قابل نوشتن باشد.
* ابزارهای `pg_dump` و `pg_restore` باید از نسخه‌ای هم‌رده یا جدیدتر از سرور PostgreSQL باشند.

## ۳. ساخت نسخه پشتیبان

### دستی

«تنظیمات ← پشتیبان‌گیری و بازیابی ← پشتیبان‌گیری همین حالا». محتوای نسخه بر اساس گزینه‌های
«پشتیبان‌گیری از تنظیمات» و «پشتیبان‌گیری از فایل‌های دستگاه‌ها» در همان صفحه تعیین می‌شود.

### خودکار

۱. «پشتیبان‌گیری خودکار روزانه» را فعال کنید.
۲. ساعت اجرا را به وقت منطقه زمانی انتخاب‌شده در تنظیمات وارد کنید (پیش‌فرض `03:00`).
۳. در هر روز حداکثر یک اجرای خودکار انجام می‌شود؛ اگر سرور در ساعت مقرر خاموش باشد، تا ۹۰ دقیقه
   بعد جبران می‌کند. نتیجه در «تاریخچه عملیات» ثبت می‌شود.

پشتیبان‌گیری خودکار را می‌توان با `BACKUP_CRON_ENABLED=false` در سرور به‌طور کامل غیرفعال کرد.

### رمزنگاری

* الگوریتم AES-256-GCM برای هر فایل، با IV تصادفی و Tag احراز اصالت.
* کلید با `scrypt(BACKUP_PASSPHRASE, "repair-workshop-backup-v1")` مشتق می‌شود و ذخیره نمی‌شود.
* نسخه رمزنگاری‌شده از رابط کاربری قابل دانلود نیست (برای جلوگیری از خروج متن‌رو). برای انتقال
  آفسایت، پوشه بسته را با ابزار فایل کپی کنید.
* **عبارت عبور را گم نکنید.** بدون آن بازیابی نسخه رمزنگاری‌شده ممکن نیست.

## ۴. بازیابی از رابط کاربری

۱. همه کاربران را خارج کنید و از انجام کار هم‌زمان جلوگیری کنید.
۲. «تنظیمات ← پشتیبان‌گیری و بازیابی» را باز کنید.
۳. در ردیف نسخه موردنظر، «بازیابی» را بزنید.
۴. نام بسته را دقیقاً تایپ کنید و بخش‌های موردنظر را انتخاب کنید:
   * **پایگاه داده:** همه تجهیزات، مشتریان، کاربران، سوابق و تنظیمات پایگاه داده به آن نسخه برمی‌گردد.
   * **تنظیمات، فیلدها و گزینه‌ها:** تنظیمات سامانه و ساختار فرم‌ها از `settings.json` بازمی‌گردد
     (کاربران و نشست‌ها تغییر نمی‌کنند).
   * **فایل‌های دستگاه‌ها:** فقط فایل‌های غایب از بسته بازگردانده می‌شوند؛ فایل موجود بازنویسی نمی‌شود.
۵. اجرای بازیابی را تأیید کنید.

پیش از هر بازیابی، سامانه به‌طور خودکار یک «نسخه ایمن» با منبع `pre_restore` می‌سازد. اگر ساخت این
نسخه ناموفق باشد، بازیابی متوقف می‌شود.

عملیات پایگاه داده با دستور زیر انجام می‌شود:

```
pg_restore --clean --if-exists --no-owner --single-transaction --dbname <DATABASE_URL> <dump>
```

`--single-transaction` باعث می‌شود در صورت خطا، تغییرات نیمه‌کاره باقی نماند و
`--clean --if-exists` اشیای قبلی را پیش از بازسازی حذف می‌کند.

> اگر نسخه پشتیبان متعلق به نسخه قدیمی‌تر نرم‌افزار باشد، پس از بازیابی یک‌بار سرویس را ری‌استارت
> کنید تا مهاجرت‌های جدید (مثل `006_phase5_settings_backup.sql`) روی پایگاه داده بازیابی‌شده اجرا شوند.
> تاریخچه عملیات در چنین حالتی دوباره ساخته می‌شود.

## ۵. بازیابی دستی روی سرور (در صورت خرابی کامل)

اگر برنامه بالا نمی‌آید یا رابط کاربری در دسترس نیست:

```powershell
# ۱) توقف سرویس
nssm stop RepairWorkshop

# ۲) اگر بسته رمزنگاری شده، فایل dump را با عبارت عبور باز کنید
#    (این کار با ابزار رمزگشایی پروژه انجام می‌شود؛ برای نسخه‌های رمزنگاری‌نشده لازم نیست)

# ۳) بازیابی پایگاه داده
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" `
  --clean --if-exists --no-owner --single-transaction `
  --dbname "postgresql://repair_app:رمز@127.0.0.1:5432/repair_workshop" `
  "D:\Backups\RepairWorkshop\backup-20261023-030000\database.dump"

# ۴) بازگرداندن تنظیمات (در صورت نیاز)
#    فایل settings.json را با یک ابزار JSON به app_settings / field_definitions / option_lists برگردانید
#    یا از دکمه بازیابی تنظیمات در همان نسخه استفاده کنید.

# ۵) شروع سرویس
nssm start RepairWorkshop
```

برای نسخه رمزنگاری‌شده، فایل `.enc` را فقط با عبارت عبور صحیح می‌توان باز کرد. اگر عبارت عبور در
دسترس نیست، نسخه‌های رمزنگاری‌نشده یا بکاپ فایل‌سیستمی دیسک را بررسی کنید.

## ۶. آزمون دوره‌ای بازیابی

حداقل هر سه ماه یک‌بار:

۱. یک پایگاه داده آزمایشی بسازید و `DATABASE_URL` موقت را به آن بدهید.
۲. یک نسخه پشتیبان واقعی را بازیابی کنید.
۳. ورود مدیر، تعداد تجهیزات، یک پرونده با تاریخچه و یک گزارش را بررسی کنید.
۴. نتیجه (تاریخ، نام بسته، مدت) را در دفتر نگهداری سرور ثبت کنید.

## ۷. سیاست پیشنهادی نگهداری

| مورد | پیشنهاد |
| --- | --- |
| نسخه روزانه | ۱۴ نسخه (حدود دو هفته) |
| نسخه ماهانه | یک نسخه در پایان هر ماه روی دیسک جداگانه |
| محل | دیسک سرور + کپی روی NAS یا حافظه خارجی |
| رمزنگاری | فعال، با عبارت عبور در گاوصندوق یا مدیر رمز سازمانی |
| آزمون بازیابی | هر سه ماه |
| فایل‌های دستگاه | Robocopy روزانه از `STORAGE_ROOT` و `UPLOADS_DIR` به دیسک دوم |

نمونه Robocopy:

```powershell
robocopy "D:\RepairStorage" "\\NAS\RepairStorageMirror" /MIR /R:2 /W:5 /LOG+:D:\Backups\filesync.log
robocopy "D:\RepairWorkshop\uploads" "\\NAS\RepairUploadsMirror" /MIR /R:2 /W:5
```

## ۸. عیب‌یابی

| نشانه | بررسی |
| --- | --- |
| «pg_dump پیدا نشد» | مقدار `PG_DUMP_PATH` و نصب PostgreSQL |
| «pg_restore پیدا نشد» | مقدار `PG_RESTORE_PATH` |
| خطای دسترسی پوشه | دسترسی کاربر سرویس به مسیر پشتیبان؛ مسیر شبکه‌ای باید با کاربر سرویس نگاشت شود |
| «رمزنگاری فعال است اما عبارت عبور تنظیم نشده» | `BACKUP_PASSPHRASE` را در `.env` تنظیم و سرویس را ری‌استارت کنید |
| «رمزگشایی ناموفق بود» | عبارت عبور با زمان ساخت نسخه یکسان نیست |
| بازیابی انجام نمی‌شود | خروج کاربران، دسترسی `pg_restore` و فضای دیسک |
| هشدار شکست در تنظیمات | متن خطا در تاریخچه عملیات و لاگ سرویس |
| نسخه خودکار ساخته نمی‌شود | فعال بودن زمان‌بندی، `BACKUP_CRON_ENABLED` و ساعت/منطقه زمانی |
