# گزارش ارزیابی نهایی نرم‌افزار مدیریت تعمیرگاه

تاریخ ارزیابی: ۱۴۰۵/۰۸/۰۱ (۲۰۲۶-۱۰-۲۳)
نسخه: ۱.۰.۰ — شاخه `freebuff/5f056bffad91fca13199f260`

## ۱. خلاصه اجرایی

| شاخص | نتیجه |
| --- | --- |
| کل موارد چک‌لیست | ۱۰۱ |
| انجام‌شده و تأییدشده با آزمون خودکار/HTTP/بازبینی مسیر داده | **۸۸** |
| پیاده‌سازی‌شده اما نیازمند آزمون پذیرش در محیط واقعی (مرورگر، ویندوز، ابزار واقعی PostgreSQL، شبکه تعمیرگاه) | **۱۳** |
| انجام‌نشده | **۰** |
| قابلیت صرفاً ظاهری بدون عملکرد | **۰** |

در این مرحله سه شکاف واقعی شناسایی و برطرف شد:

1. **وضعیت‌های دستگاه ثابت بودند** و مدیر نمی‌توانست وضعیت جدید تعریف کند (بند ۸ چک‌لیست).
2. **سوابق دستگاه‌های هر مشتری** در بخش مشتریان قابل مشاهده نبود؛ فقط تعداد دستگاه نمایش داده می‌شد (بند ۳).
3. **رسید تحویل** جدا از رسید پذیرش وجود نداشت و زمان تحویل واقعی در نسخه چاپی دیده نمی‌شد (بند ۹).

هر سه مورد کامل پیاده‌سازی، به API واقعی متصل و با تست سرور/کلاینت و آزمون دود HTTP بررسی شدند.

روش ارزیابی: اجرای واقعی سرور NestJS روی PostgreSQL (مهاجرت‌های ۰۰۱ تا ۰۰۷)، تست‌های یکپارچگی با
HTTP و پایگاه داده واقعی، تست‌های DOM با React Testing Library، آزمون دود ۵۷ بررسی روی سرور در حال
اجرا، بررسی نوع‌ها (`tsc --noEmit`) و ساخت تولیدی. هیچ موردی فقط بر اساس وجود دکمه یا صفحه تأیید نشد.

## ۲. نتایج آزمون‌ها

| مجموعه | فرمان | نتیجه |
| --- | --- | --- |
| نوع‌ها | `npm run typecheck` | موفق (سرور و کلاینت، بدون خطا) |
| تست سرور | `npm run test:server` | **۹۳ تست موفق** در ۸ سوئیت با PostgreSQL واقعی |
| تست کلاینت | `npm run test:client` | **۳۱ تست موفق** در ۱۱ فایل |
| ساخت تولیدی | `npm run build` | موفق (کلاینت + سرور) |
| آزمون دود HTTP | `node scripts/smoke-test.mjs` | **۵۷ بررسی موفق** روی سرور در حال اجرا |

تست‌های جدید این مرحله:

- `server/test/phase6.spec.ts` — ۷ تست: فهرست وضعیت‌ها، تعریف وضعیت سفارشی، تغییر وضعیت و
  تاریخچه، فیلتر، نمودار/جدول گزارش، ممنوعیت حذف و غیرفعال‌سازی، محافظت از وضعیت‌های پیش‌فرض،
  سوابق دستگاه‌های مشتری و ثبت زمان تحویل.
- `client/src/lib/device-status.test.ts` — ترکیب وضعیت‌های پیش‌فرض با وضعیت‌های مدیر، حذف
  وضعیت غیرفعال و اصلاح رنگ نامعتبر.
- `client/src/features/customers/customer-devices-dialog.test.tsx` — نمایش سوابق دستگاه‌های
  مشتری و وضعیت خالی.
- `client/src/features/devices/device-print-page.test.tsx` — محتوای رسید پذیرش و رسید تحویل.

آزمون دود شامل این موارد جدید است: تعریف وضعیت سفارشی، ظهور آن در فهرست وضعیت‌ها، پذیرش دستگاه
دوم، تغییر وضعیت با برچسب صحیح، فیلتر فهرست، سوابق دو دستگاه در پرونده مشتری، نمودار و جدول گزارش
و **پنج نشست هم‌زمان** با ورود، پروفایل و فهرست تجهیزات.

## ۵. قابلیت‌هایی که فقط ظاهری هستند

پس از رفع سه شکاف بالا، **هیچ دکمه، فرم یا صفحه‌ای بدون اتصال به API باقی نمانده است**. بررسی‌های زیر
انجام شد:

- همه دکمه‌های فهرست‌ها (جست‌وجو، فیلتر، مرتب‌سازی، صفحه‌بندی، ستون‌ها، چاپ، خروجی) به درخواست
  واقعی یا مسیر چاپ متصل‌اند و در تست‌های DOM/آزمون دود فراخوانی شدند.
- تنظیمات ظاهر، تقویم، پشتیبان‌گیری، فیلدها، فهرست‌ها و وضعیت‌ها در پایگاه داده ذخیره و در
  درخواست بعدی خوانده می‌شوند (آزمون دود).
- نمودارها و کارت‌های داشبورد از API تغذیه می‌شوند؛ داده ثابت یا نمونه در کلاینت وجود ندارد.
- تنها کنترل‌هایی که تأیید نهایی‌شان به محیط واقعی وابسته است، در بخش ۶ فهرست شده‌اند و هیچ‌کدام
  «صرفاً ظاهری» نیستند.

## ۶. موارد نیازمند آزمون پذیرش در محیط واقعی

این ۱۳ مورد کد کامل دارند؛ فقط تأیید نهایی محیطی باقی است:

1. **بازکردن پوشه از کلاینت (۴.۷ و ۴.۱۲):** نصب `tools/storage-helper/install.ps1` روی دو کلاینت
   ویندوزی، کلیک «بازکردن پوشه» و بررسی بازشدن Explorer با مسیر شبکه.
2. **خروجی PDF (۷.۶ و ۷.۱۱):** ساخت گزارش با لوگو و فیلتر، دانلود PDF، بررسی صفحه‌بندی، تصویر
   نمودار، تاریخ شمسی و متن فارسی.
3. **خروجی PNG (۷.۹):** ذخیره تصویر هر نمودار از منوی نمودار.
4. **ظاهر و واکنش‌گرایی (۹.۳، ۹.۵، ۹.۶، ۹.۷):** بازبینی در عرض ۱۳۶۶، ۱۹۲۰ و تبلت؛ بررسی منو،
   فرم‌ها و جدول‌ها.
5. **نصب سرور (۱۰.۱):** نصب به‌صورت سرویس ویندوز/NSSM طبق `DEPLOYMENT.md` و اجرای پس از ری‌استارت.
6. **پنج کلاینت واقعی (۱۰.۲):** اتصال پنج رایانه هم‌زمان، ثبت هم‌زمان پذیرش و بررسی نبود تداخل.
7. **بازیابی واقعی (۱۰.۹):** تهیه بکاپ با `pg_dump` نصب‌شده، بازیابی روی پایگاه آزمایشی با
   `pg_restore` و مقایسه تعداد رکوردها و فایل‌ها.
8. **آزمون میدانی (۱۰.۱۰):** یک هفته استفاده واقعی با داده واقعی و ثبت بازخورد کاربران.

برای هر مورد، فرم پذیرش و معیار قبولی در `docs/BACKUP-RESTORE.md` و `docs/DEPLOYMENT.md` آمده است.
